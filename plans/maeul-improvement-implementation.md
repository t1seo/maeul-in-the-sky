## Shared contracts: freeze in T01 before dependent edits

The following names and semantics are binding. T01 owns the new definitions and parsers; later owners request changes through root. New coherent modules, including extracted source modules, stay at or below 250 executable LOC. Large geometry catalogs split by family and then by renderer; do not hide executable code in strings solely to evade the limit.

### 1. Options and compatibility

Place portable types in `src/core/render-options.ts`, `scene-types.ts`, `snapshot-types.ts` and parsers in `src/core/settings/`. Add optional fields to `ThemeOptions`: `motion: 'full'|'subtle'|'off'`, `layout: 'banner'|'card'`, `villageStyle: 'classic'|'korean'`, `normalization: {kind:'relative'}|{kind:'fixed'; maxCount:number}`, and `layoutSeed?: string`. Keep existing required fields and existing exports. `Theme.render` still returns exactly `{dark, light}`; metadata is supplied by the new rendering API, not required of custom themes.

`ResolvedRenderSettings` includes resolved preset/density, title, hemisphere, motion, layout, style, normalization, and optional seed override. Precedence: explicit CLI/Action/UI field > loaded settings > selected preset defaults > library defaults. An omitted CLI flag must not silently overwrite loaded settings with Commander defaults. Invalid explicit values fail rather than falling back. Width/height continue to set display dimensions; `layout` determines the logical viewBox.

`renderTerrain(data, options): TerrainRenderResult` is the new pure portable entry, returning `{dark, light, metadata}`. `prepareTerrainScene(data, options): TerrainScene` resolves data/placement once; `renderTerrainScene(scene, mode, options): string` shades that scene. Terrain `Theme.render` delegates and projects `{dark, light}`. `maeul-in-the-sky/browser` exports these functions, portable parsers, settings, catalog and related types. The main Node export retains everything and adds these APIs. Browser bundle contains no `fs`, `path`, `process`, `Buffer`, Actions SDK, fetch client or native PNG dependency.

### 2. Calendar, normalization and stable layout

- Add optional `week`/`day` fields to legacy `GridCell` for source compatibility; keep existing `IsoCell.week`/`day` required and add optional date/count/absolute-week metadata there. All new prepared scene cells have required `date`, `week`, `day`, `absoluteWeek`, `count`, `level100`, and geometry. Legacy `toIsoCells` callers without coordinates derive them from ISO dates, never from array order. Invalid/duplicate dates remain errors.
- Define `week` as UTC Sunday distance from the earliest supplied Sunday's week, including absent intervening weeks; `day` is UTC weekday. Missing dates emit no contribution cell, tooltip, streak day or fake zero. Known zero-count dates emit real level-zero cells. Calendar padding may be decorative only and must be marked as such.
- `absoluteWeek = floor((utcSundayMs - Date.UTC(1970,0,4))/604800000)`. Compute seed root from `layoutVersion=1`, trimmed lower-case username and explicit seed override, never mode, title, array index or year. Salt independent hashes with absolute date/week and purpose (`biome`, `asset`, `variant`, `wonder`); avoid advancing one global PRNG across a variable list of dates. Biome noise uses absolute week coordinates and a fixed boundary halo, not range length.
- Relative normalization keeps current behavior: sort positive counts, use index `min(floor(n*0.9),n-1)`, fallback max `1`; zero → level `0`, positive → `clamp(round(sqrt(clamp(count/max,0,1))*98)+1,1,99)`. Fixed max must be finite and strictly positive. Never persist a derived relative max as though the user requested fixed normalization.
- Archive comparison defaults to one **pooled nonzero P90 across all selected snapshots**, persisted as fixed max in the comparison manifest and shown in the UI/legend. Explicit fixed max overrides it. Equal counts therefore have equal levels/heights across years. Per-year relative viewing is allowed only outside the comparison and clearly labelled.
- Promise stable random identities for shared dates, and identical geometry for dark/light. With fixed normalization and unchanged local context, overlapping interior dates retain terrain/ordinary placements after a rolling shift; screen positions translate with the date window. Relative P90 changes may change heights; neighbor eligibility and the global Wonder budget may change actual selections. Document these limits and test them separately, instead of promising immutable terrain across all changed inputs. Calendar seasons derive from absolute dates and hemisphere, not a shifted array index.

### 3. Scene, metadata and catalog

`TerrainScene` is a readonly, JSON-safe version-1 object: username, supplied date range, resolved settings, normalization summary, complete stats, cells, biome entries, ordinary placements, Wonder placements, neighborhood paths, and logical bounds. It contains no mode colors, SVG fragments, Maps, functions, clocks or token material. Stable ordering and key construction make equal inputs byte-reproducible. Internal lookups may be Maps but are not the serialization contract.

`TerrainMetadata` includes `schemaVersion:1`, `layoutVersion:1`, username, year, actual `fromDate`/`toDate`, data-day/missing-day counts, stats, normalization `{kind,maxCount,source}`, layout seed policy, bounds, and per-cell `{date,count,week,day,level100,biome,assetIds,wonderIds}`. Placements have stable IDs, type/catalog ID, anchor date, footprint and draw order. Wonder metadata additionally records tier, achieved thresholds/current values and an explanation derived from the actual selection gates; it must not fabricate an unlock or a contribution. Relative and fixed metadata distinguish their origin.

All drawable ordinary assets, Wonders and neighborhood connectors join a common deterministic draw list ordered by isometric ground depth, anchor week/day and stable ID; explicit sky/water/block foreground layers remain separate. Keep a fixture with a tall Wonder behind a foreground house. No unconditional last-pass Wonder layer.

Catalog records contain stable `id`, family (`nature|building|decoration|wonder|korean`), display names, bounds/anchor, seasons, variants, motion capability and renderer. Public serialized catalog omits the function. Count base IDs, seasonal IDs and Wonders separately; generate totals and previews from the same registry. `assets.ts` and `epics.ts` remain compatibility facades. Korean IDs are `hanok`, `pavilion`, `stoneWall`, `onggi`; require four recognizable original vector drawings, not renamed classic shapes.

### 4. Settings, snapshots, archive and data trust

`SettingsV1 = {schemaVersion:1, kind:'maeul-settings', username, year?:number, settings:ResolvedRenderSettings}`. `SnapshotV1 = {schemaVersion:1, kind:'maeul-snapshot', username, year, weeks, settings, source:{kind:'github'|'import'|'sample', fetchedAt?:string}}`. Stats and scene are recomputed from weeks; untrusted imported totals/markup cannot override them. Optional `fetchedAt` is source provenance only and never enters render/seed hashes. Serialize in a documented key order with ISO dates and no undefined values. Reject unknown versions, duplicate dates, invalid dates, negative/noninteger counts, invalid levels, invalid options and malformed JSON with field-specific errors. Maximum import: 2 MiB, 20,000 contribution days across at most 20 snapshots; reject before expensive rendering.

`ArchiveV1 = {schemaVersion:1, kind:'maeul-archive', snapshots:SnapshotV1[], comparison:{normalization:{kind:'fixed',maxCount}, years:number[]}}`. Sort by year; duplicate username/year entries require explicit replacement in UI, never silent overwrite. Compare 2–5 selections of the same username; archive may store up to 20 entries. Preserve stored sources; settings-only links must not imply they contain contribution data.
