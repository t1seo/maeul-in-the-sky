# 세계 확장 벤치마킹: 넓은 자연과 탐험할 수 있는 마을

조사일: 2026-09-19. 범위: 개발사·배급사 공식 소개 및 원 저장소 5종. 이 문서는 아이디에이션 근거이며 구현 계획의 확정이나 기능 구현을 뜻하지 않습니다.

**추천 방향은 월별 군도를 먼저 만들고, 섬 사이의 생활 움직임을 더한 뒤, 별도 웹 페이지에서 3D로 탐험하도록 확장하는 것입니다.** 건물 하나를 크게 만드는 방식보다 숲·수역·작은 시가지가 연결된 풍경이 현재의 자연 중심 정체성에 더 잘 맞는다고 판단했습니다. 이는 아래 자료를 바탕으로 한 프로젝트 제안입니다.

아래에서 **확인**은 공식 설명의 사실, **제안**은 아직 구현·사용자 검증하지 않은 적용 아이디어입니다. 다른 게임의 그래픽·모델·사운드를 가져오는 제안은 포함하지 않았습니다.

## 1. Dorfromantik — 타일이 모여 하나의 풍경이 되는 방식

**확인:** Toukana는 타일을 배치해 마을 풍경을 확장하는 게임으로 소개합니다. 다양한 바이옴, 새 타일의 발견·해금, 퀘스트를 명시합니다. 공식 프레스킷은 손으로 그린 보드게임 같은 화풍과 여러 플레이 모드를 설명합니다. [공식 소개](https://www.toukana.com/dorfromantik), [공식 프레스킷](https://www.toukana.com/dorfromantik/presskit)

**제안:** 날짜 하나의 장식보다 날짜들이 함께 만드는 지형을 강조하면 좋겠습니다. 한 달을 하나의 섬으로 묶고, 숲·논밭·호수·마을이 섬 안에서 이어지게 구성합니다. 12개 섬을 펼치면 1년의 군도가 되고, 여러 해는 군도끼리 연결됩니다. 기존 배너는 이 세계의 축약 지도 역할을 맡습니다.

**확인할 가정:** 넓은 지도가 긴 달력 띠보다 보기 좋은지, 날짜를 찾는 일이 어려워지지 않는지 함께 확인해야 합니다. 작은 화면에서는 월 이름과 섬 선택, 섬 안에서는 날짜 조회가 필요합니다. 해금 수치·자연 비율은 이 게임의 규칙을 가져오는 대신 프로젝트의 별도 가설로 정해야 합니다.

## 2. Townscaper — 배치에 반응하는 연결 건축

**확인:** Raw Fury는 불규칙 격자에 놓인 블록의 구성에 따라 집·아치·계단·다리·뒤뜰이 자동으로 만들어진다고 설명합니다. 목표나 실패 부담이 적은 건축 장난감이라는 성격도 명시합니다. [배급사 공식 소개](https://rawfury.com/games/townscaper/)

**제안:** 건물을 무작위로 늘리기보다 관계에서 새로운 외형을 만들면 좋겠습니다. 한옥 두 채 사이에는 공동 마당, 물가의 작은 집 앞에는 잔교, 높이가 다른 길 사이에는 계단, 두 섬 사이에는 다리가 나타나는 방식입니다. 도시 지역도 같은 건물의 반복 대신 역·시장·광장·주택가가 구획을 이루도록 만들 수 있습니다.

**확인할 가정:** 연관 장식이 풍경의 응집감을 높이는지, 날짜별 기여에 대응하는 주 보상을 가리지 않는지 확인해야 합니다. 기존 날짜 보상과 별개인 연결 요소로 두고, 원래 기여 수치를 바꾸지 않는 설계가 적절합니다. 알고리즘 전체를 복제할 필요 없이 한두 가지 이웃 규칙으로 먼저 평가할 수 있습니다.

## 3. Tiny Glade — 작은 움직임으로 살아 있는 장소 만들기

**확인:** 개발사 Pounce Light의 공식 Steam 소개는 격자에 얽매이지 않는 건축과 배치에 반응하는 세부 표현을 설명합니다. 길과 건물이 만나면 문이 생기는 예시, 담쟁이, 길을 걷는 양, 밤의 반딧불을 직접 제시합니다. [개발사 공식 제품 소개](https://store.steampowered.com/app/2198150/Tiny_Glade/)

**제안:** 동물을 모든 칸에 추가하기보다 숲의 사슴, 호수의 오리, 마을의 주민, 두 섬 사이를 왕복하는 작은 배처럼 서식지와 경로를 연결하면 좋겠습니다. 기여가 꾸준한 기간에는 저녁 창문에 불이 켜지고, 광장에 장터가 열리고, 여름 강가에 반딧불이 모이는 식으로 생활 장면을 풍부하게 만들 수 있습니다. 봄 꽃길·여름 나룻배·가을 추수·겨울 온실은 계절별 작은 이야기 후보입니다.

**확인할 가정:** 움직이는 개수가 많을수록 좋은 것은 아닙니다. 작은 배너에서는 한두 움직임으로도 충분한지 평가해야 합니다. 쉬는 날에 건물이나 숲이 사라지는 벌점은 피하고, 움직임을 줄이는 설정에서도 완성된 정적 풍경이 남도록 제안합니다.

## 4. GitHub Skyline — 1년을 기념하는 3D 소장품

**확인:** GitHub 조직의 `gh-skyline`은 기여 그래프를 3D 프린팅용 STL로 만드는 GitHub CLI 확장입니다. 단일 연도와 여러 연도를 지원하고, 생성한 STL을 GitHub 저장소에 올려 볼 수 있다고 안내합니다. [공식 저장소 README, 조사 시점 고정 커밋](https://github.com/github/gh-skyline/blob/5245b2fc95250075cac37d24a4cd9b09258de5a8/README.md)

**제안:** 탐험 기능 외에도 ‘올해의 섬’ 기념품을 생각할 수 있습니다. 연말 엽서, 회전하는 짧은 영상, 3D 모델 내보내기를 차례로 확장하면 자신의 기록을 보관하고 공유할 이유가 생깁니다. 한 해의 완성 모습을 저장한 뒤 다음 해에는 새 섬을 여는 방식도 어울립니다.

**확인할 가정:** 현재 SVG를 그대로 STL로 바꾸면 완성된 입체 마을이 되지는 않습니다. 출력 가능한 바닥 두께·연결 구조·작은 나무 가지의 강도 등은 별도 모델 설계가 필요합니다. 초기에는 사진·엽서부터 확인하는 편이 빠릅니다. 이는 제작 난도에 관한 판단이며 Skyline의 성능 평가가 아닙니다.

## 5. GitCity — 프로필 이미지와 탐험 페이지의 연결

**확인:** 여기서 조사한 것은 **Rishabh Bhartiya의 GitCity**입니다. 원 저장소는 GitHub 기여 기록의 상호작용형 3D 도시를 소개하며, README에는 SVG 이미지를 개인 도시 페이지로 연결하는 삽입 예시가 있습니다. 포트폴리오용 상호작용 iframe 예시도 별도로 제공합니다. [원 저장소 README, 조사 시점 고정 커밋](https://github.com/rishabhbhartiya/GitCity/blob/f01554aabbfb9a04416f94abe4fd0e435a87bdbc/README.md), [연결된 서비스](https://gitcity.natrajx.in/)

**제안:** GitHub 프로필에서는 지금처럼 가볍게 읽히는 SVG를 보여주고, 누르면 넓은 섬을 회전·확대하는 웹 탐험 화면으로 연결하면 좋겠습니다. 웹 화면에서는 계절·시간대 전환, 특정 날짜로 이동, 사진 찍기, 열차나 배를 따라가는 카메라를 제공할 수 있습니다. 자연과 한국 시골·한옥을 중심에 두면 도시 스카이라인 도구와 구별되는 방향이 됩니다.

**범위:** 같은 이름을 쓰는 `gitcity.io`, `thegitcity.com`, 다른 Git City 저장소의 기능을 이 제품의 기능으로 섞지 않았습니다. 저장소 소개를 확인했으며 배포 서비스의 모든 기능·성능·개인정보 처리 주장을 검증한 것은 아닙니다. 이 사례를 GitHub README 내부에서 iframe이 실행된다는 근거로 해석해서는 안 됩니다.

## 프로젝트 적용을 위한 세 가지 우선 추천

| 순서 | 제안 | 사용자가 보게 될 장면 | 먼저 검증할 것 |
| --- | --- | --- | --- |
| 1 | **12개월 하늘 군도** | 긴 띠 대신 넓게 펼쳐진 섬, 이어지는 숲·강·작은 시가지, 섬 사이의 다리 | 같은 날짜·기여 입력을 보존하면서 구도와 날짜 탐색이 개선되는지 |
| 2 | **살아 있는 생활 장면** | 한옥 마당의 장터, 숲 가장자리의 동물, 섬을 오가는 배, 저녁 창문 불빛 | 같은 수의 에셋으로도 재미가 커지는지, 축소·저성능·모션 끄기에서 잘 보이는지 |
| 3 | **웹 3D 탐험과 사진 모드** | 섬 회전·확대, 원하는 계절·빛으로 엽서 촬영, 자신의 풍경 공유 | 일부 대표 에셋만 입체화해도 현재 화풍의 매력이 유지되는지, 모바일에서 탐색 가능한지 |

이 순서는 제안입니다. 완전한 3D가 가장 큰 시각적 변화이지만, 지도 구도와 지역의 연결감은 기존 표현에서도 먼저 시험할 수 있습니다. 작은 3D 섬 한 개의 탐험 시제품을 병행한다면 본격 모델 제작 전에 품질 방향을 판단할 수 있습니다.

## 현재 구조와 연결할 때 지켜야 할 사항

현재 장면에는 날짜·기여 수·높이·바이옴·자산 ID·변형·계절 효과가 구조화되어 있고, `layoutVersion`과 시드 정책이 있습니다. 다만 좌표·배치 경계는 현재의 2D 등각 표현을 포함하며, 렌더 설정의 레이아웃은 `banner`와 `card`입니다. 이 구조는 새 뷰의 데이터 출발점이 될 수 있지만, 이미 완성된 3D 메시가 있다는 뜻은 아닙니다. [장면 타입](../src/core/scene-types.ts), [렌더 설정](../src/core/render-options.ts)

- 더 넓은 풍경의 장식 공간과 실제 날짜 셀은 의미를 분리하는 편이 좋겠습니다. 꾸민 공간을 기여가 있었던 날처럼 표시하지 않도록 합니다.
- 날짜와 시드가 같으면 같은 세계를 다시 볼 수 있어야 합니다. 새 지도 배치 방식은 버전을 명시하고, 과거의 저장 장면도 열 수 있도록 제안합니다.
- 자연·도시 비중은 사용자 취향으로 조절하되, 초기 기본값은 자연 중심으로 평가하면 좋겠습니다. 특정 비율이 최적이라는 외부 근거는 이번 조사에서 확인하지 않았습니다.
- 장기 목표는 활동량 경쟁보다 ‘내 시간이 쌓여 생긴 장소’에 두는 편을 권합니다. 꾸준함은 축제·빛·생활의 풍부함으로 표현하고, 휴식일에는 기존 장소를 보존합니다.

외부 예시에서는 구조·상호작용·보상의 원칙을 참고했습니다. 실제 에셋을 가져오거나 코드·라이선스를 도입하는 작업은 이 조사에 포함하지 않았습니다.
