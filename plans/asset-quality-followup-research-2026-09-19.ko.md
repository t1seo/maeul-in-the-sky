# 마을 에셋 품질·한국 시골·픽셀아트·기여 보상 후속 리서치

조사일: 2026-09-19 · 코드 기준: `2b608bcfda7746723dd1af30c554e3c944afd32b` · 범위: 조사 및 구현 제안

코드 설명은 조사 초기에 확인한 상태를 기준으로 합니다. 조사 중 다른 작업자가 진행한 공유 작업트리의 동시 편집은 이 문서의 구현 완료 사실로 포함하지 않았습니다.

**우선순위는 고기여일의 확정 보상, 실제 표시 크기에 맞춘 조형, 한국풍 선택 풀의 완결입니다.** 픽셀아트는 별도의 정수 격자 출력 경로로 설계하는 편이 적절합니다. 아래의 수치·에셋 구성·통과 기준은 구현 검토용 제안이며, 이미 구현되었거나 사용자 평가로 검증된 결과가 아닙니다.

[기존 조사](asset-redesign-research-2026-09-19.ko.md)의 미니어처 SVG 방향과 대표 12종 제작 제안을 전제로 합니다. 이번에는 참고작을 더 나열하기보다, 보상 누락·문화적 혼합·소품 관계·픽셀 격자·모션 예산·재현성에 대한 구체적인 변경점을 조사했습니다. 외부 근거는 공식 문서, 표준 작성 기관, 해당 제작자의 직접 게시물만 사용했습니다.

## 먼저 고정해야 할 데이터 의미

이 프로젝트가 받는 값은 **하루의 GitHub 기여 수이며 커밋 수가 아닙니다.** GraphQL의 `ContributionCalendarDay.contributionCount`는 해당 날짜의 기여 수이고, `contributionLevel`은 다른 날짜와 비교한 상대 수준입니다. 현재 쿼리도 날짜·기여 수·기여 수준을 요청하므로, 이 응답만으로 커밋 수를 분리하거나 추정할 수 없습니다. [GitHub GraphQL 공식 문서](https://docs.github.com/en/graphql/reference/users#contributioncalendarday), [현재 쿼리](../src/api/queries.ts).

GitHub의 프로필 기여에는 저장소 생성·포크와, 조건을 충족한 커밋·이슈·PR·PR 리뷰·Discussion 활동 등이 포함됩니다. 커밋은 계정과 연결된 이메일, 포크가 아닌 저장소, 기본 브랜치 또는 `gh-pages` 등 공식 집계 조건을 충족해야 합니다. 비공개 기여를 공개하면 접근 권한이 없는 사람에게는 일별 수만 보일 수 있습니다. 따라서 문구는 `오늘 25회 기여`, `일별 기여 보상`으로 쓰고, 받은 `date`와 `count`를 유지해야 합니다. 이 수치를 생산성이나 작업 품질로 해석하지 않습니다. [GitHub 프로필 기여 공식 기준](https://docs.github.com/en/account-and-profile/reference/profile-contributions-reference).

`count: 0`과 데이터에 없는 날짜도 구별합니다. 0인 날에는 기존의 자연 장식이 남을 수 있지만 보상·주거·경작지로 활동을 만들어내면 안 됩니다. 누락일은 데이터 계약상 누락으로 유지하고, 카탈로그 품질을 보여주기 위해 기여 수를 보충하지 않습니다. 기존 장식은 `decorative: true`로 구별됩니다. [장식 배치](../src/themes/terrain/scene/placements.ts), [일별 메타데이터](../src/core/scene-types.ts).

### 1. 고기여일에는 확률과 별개로 보상을 확정합니다

**제안:** 기존 100단계 지형은 유지하고, 원래 `count`에서 별도의 `rewardTier`를 계산합니다. 시작 검토값은 아래와 같습니다. GitHub가 정한 등급이 아니라 이 제품의 시각 규칙입니다.

| 일별 기여 수 | 보상 단계 | 정지 화면에서 보일 차이                |
| ------------ | --------- | -------------------------------------- |
| 0            | 0         | 보상 없음, 기존 자연 장식만 허용       |
| 1~4          | 1         | 작은 단일 장식                         |
| 5~9          | 2         | 하나의 큰 덩어리로 읽히는 풍성한 장식  |
| 10~24        | 3         | 구별되는 기단 또는 마당 형태           |
| 25~49        | 4         | 타일 앞면의 넓은 강조 면과 상위 실루엣 |
| 50 이상      | 5         | 강조 면에 굵은 문양을 더한 최고 단계   |

보상은 타일별 의미이고, 집·나무·물 위에서도 같은 단계를 표현할 수 있어야 합니다. 강 위에 집을 강제로 세우기보다 물가용 문양을 쓰고, Wonder가 차지한 날짜에도 동일한 보상 신호를 합성합니다. 다른 날의 활동이나 `density`를 바꿔도 같은 날짜의 보상 단계가 내려가지 않게 합니다. 최고 단계 이후에는 그림을 계속 키우지 않고 원래 수치를 메타데이터와 상세 정보에 보존합니다.

**구현 영향:** 장면 준비에서 보상 단계를 저장하고, 날짜에 대응하는 지형/에셋 렌더러가 이를 읽게 합니다. 보상을 일반 에셋 추첨이나 `MAX_EPIC_BUDGET`에 넣으면 보장 조건이 다시 깨집니다. 장면·메타데이터 타입 확장이 필요하고, 높이 범례와 별도로 보상 기준을 짧게 설명해야 합니다. 단조 증가는 보상 단계에 대한 보장이지, 임의의 다른 장면보다 건물이 언제나 크게 보인다는 보장은 아닙니다. [적용 지점](../src/themes/terrain/scene/prepare.ts), [타입](../src/core/scene-types.ts), [현재 높이 범례](../src/themes/terrain/scene/legend.ts).

**통과 기준:** 같은 날짜의 수만 `0→1→5→10→25→50→100`으로 바꾸면 단계가 `0→1→2→3→4→5→5`가 됩니다. P90 상한이 달라져도, 주변이 모두 0이어도, 밀도가 낮아도 단계가 유지되어야 합니다. 0일에는 보상 기하 요소가 없어야 하며, `motion: off`에서도 상위 단계를 식별할 수 있어야 합니다. 데이터 명칭의 근거는 [GitHub의 일별 기여 수 정의](https://docs.github.com/en/graphql/reference/users#contributioncalendarday)입니다.

### 2. 작은 크기용 조형과 가림 규칙을 제작 기준에 넣습니다

기존 조사에서 나무 bounds 높이는 390px 배너에서 약 5px, 카드에서 약 9px였습니다. 이는 이전 조사에서 계산한 값이며 이번에 새로 측정한 값은 아닙니다. 제작자 Pedro Medeiros도 낮은 해상도에서는 특징을 선택하고, 단순한 광원과 제한된 색으로 형태를 전달하며, 공간이 부족하면 외곽선을 줄이는 접근을 설명합니다. 이를 현재 SVG의 작은 표시 크기에 적용하는 것은 연구자의 제안입니다. [기존 크기 계산](asset-redesign-research-2026-09-19/inventory-and-scale.json), [제작자 원문](https://saint11.art/blog/thoughts_on_low_resolution/).

**제안:** 대표 12종에 각각 ‘가장 먼저 읽혀야 할 특징 하나’를 지정합니다. 소나무는 비대칭 수관 층, 버드나무는 아래로 늘어진 덩어리, 한옥은 처마 곡선, 초가는 두툼하고 둥근 지붕, 정자는 기둥 사이의 빈 공간입니다. 밝은 면·중간 면·그림자 면을 재료 역할로 구분하고, 미세한 선보다 면적과 명도 차이를 먼저 맞춥니다. 어두운 모드에서도 문·기둥·수관이 배경과 합쳐지지 않게 합니다.

간략형에서는 창살·기와 선·점 무늬를 생략하고 큰 특징을 남깁니다. 상세형은 카탈로그와 충분히 큰 출력에 사용합니다. 선택 기준은 생성 시 알 수 있는 출력 설정으로 고정하고, 외부 `<img>`의 실제 CSS 폭을 SVG 내부 JavaScript로 측정하는 구조를 만들지 않습니다. README에 쓰일 기본형은 390px 축소에서 읽히도록 제작합니다.

**구현 영향:** 기존 렌더러와 bounds를 함께 갱신하되, 일반 에셋·보상 장식의 최대 외곽 범위를 먼저 정합니다. 보상 등급이 올랐다는 이유만으로 이 범위를 늘리지 않습니다. 겹침이 생기면 뒤 건물의 지붕이나 보상 문양을 가리는 앞쪽 보조 소품부터 줄이고, 주거/보상 자체를 삭제하지 않습니다. 렌더 표현이 달라도 같은 날짜·에셋 ID·보상 의미를 유지합니다. [bounds](../src/themes/terrain/assets/bounds.ts), [깊이 정렬](../src/themes/terrain/scene/depth.ts).

**통과 기준:** 대표 에셋을 840px 배너, 390px 배너, 390px 카드에서 모션 없이 확인합니다. 흑백으로도 집·나무·정자와 상위 보상 신호가 구별되어야 하고, 창살을 제거해도 한옥의 정체성이 유지되어야 합니다. 밀집 장면에서 주요 지붕/보상 문양이 완전히 가려지는 사례를 실패로 기록합니다. 새로운 픽셀 측정이나 식별률은 구현 후 수집해야 합니다.

### 3. 한국 시골을 건축물·농지·생활 소품의 조합으로 완성합니다

UNESCO는 하회·양동의 특징을 목조 주택·초가·정자뿐 아니라 숲·강·열린 농경지가 어우러진 배치로 설명합니다. 이 자료는 특정 역사 마을의 근거이며, 한국의 모든 시골을 같은 모습으로 정의하지는 않습니다. 장 담그기 자료는 발효·보관을 이어온 생활 문화를, FAO의 제주 밭담 자료는 검은 화산석 담의 지역적 맥락을 보여줍니다. [UNESCO 하회·양동](https://whc.unesco.org/en/list/1324/), [UNESCO 장 담그기](https://ich.unesco.org/en/RL/knowledge-beliefs-and-practices-related-to-jang-making-in-the-republic-of-korea-01975), [FAO 제주 밭담](https://www.fao.org/giahs/giahs-around-the-world/korea-jeju-batdam-agricultural-system/en).

**제안:** 첫 한국 시골 조합은 아래 6개 역할로 제한합니다. 이미 존재하는 논·항아리·정자를 새 ID로 중복 제작하지 않습니다.

| 역할             | 제작/수정 내용                            | 작은 크기의 핵심                |
| ---------------- | ----------------------------------------- | ------------------------------- |
| 한옥 `hanok`     | 처마와 지붕 덩어리, 벽의 명도 정리        | 굽은 처마와 짙은 지붕           |
| 초가, 신규 ID    | 낮은 벽과 두꺼운 볏짚 지붕 제작           | 둥근 지붕의 큰 실루엣           |
| 논 `ricePaddy`   | 논둑·물 면·벼의 큰 띠를 정리              | 평평한 경계와 반복된 작물 띠    |
| 장독대 조합      | 기존 `onggi`와 낮은 받침을 한 배치로 구성 | 크기가 다른 항아리 2~3개의 묶음 |
| 담장 `stoneWall` | 마당 경계형 조각과 열린 입구 구성         | 낮고 끊어진 담의 윤곽           |
| 정자 `pavilion`  | 지붕을 받치는 기둥과 빈 공간 강조         | 집과 다른 열린 구조             |

초가를 낮은 기여의 ‘열등한 집’으로만 쓰지 않습니다. 지붕 재료와 활동 보상은 분리하고, 같은 초가·한옥 가족 안에서 마당·주변 식생·정적 보상 문양이 풍성해지게 합니다. 색·형태·배치의 구체적인 선택은 위 문화 자료에서 도출한 자체 디자인 제안입니다. 제주식 검은 밭담을 쓰려면 그 지역성을 명시한 별도 변형으로 다루고, 역사 마을 자료와 무차별적으로 섞지 않습니다.

**구현 영향:** `style: korean`이 상위 일반 에셋 풀과 Wonders까지 일관되게 작동하도록 문화별 허용 목록을 둡니다. 예를 들어 `cathedral`·`clocktower`를 계속 남기기보다 한옥 마당 조합·누정 등으로 대응하고, `torii`·`mountFuji` 같은 지역 특정 Wonders는 한국풍에서 제외합니다. 기존 보편적 자연 Wonder는 별도로 허용할 수 있습니다. 새 한국형 Wonder를 넣을 경우 일반 193종과 별개인 Wonder 카탈로그·조건·bounds에 등록해야 합니다. [스타일 적용](../src/themes/terrain/assets/style-pool.ts), [일반 카탈로그](../src/themes/terrain/assets/catalog.ts), [Wonder 카탈로그](../src/themes/terrain/epics/catalog.ts).

**통과 기준:** 상위 레벨까지 올라간 한국풍 fixture에서 허용 목록 밖의 건축물과 지역 특정 Wonder가 선택되지 않아야 합니다. 기여 수·계절·문화 스타일을 고정하면 밝은/어두운 모드의 배치가 같아야 하고, 한국풍의 상위 단계에서도 농촌 조형을 유지해야 합니다.

### 4. 소품에 소유 건물과 접지 방향을 부여합니다

현재 일반 에셋은 날짜별로 1~2개의 슬롯을 추첨합니다. 집과 항아리가 모두 있어도 서로 관련 없는 위치에 놓일 수 있습니다. 기존 이웃 길은 주거를 탐색해 연결하므로, 이 관계를 활용할 여지가 있습니다. [선택 슬롯](../src/themes/terrain/assets/selection.ts), [이웃 길](../src/themes/terrain/scene/neighborhood.ts). 건물 주변의 경관까지 함께 다루자는 방향은 [UNESCO의 마을 배치 설명](https://whc.unesco.org/en/list/1324/)을 참고한 제안입니다.

**제안:** 집 앞 마당에 항아리, 담장 끝에 입구, 논 가장자리에 논둑을 두는 작은 관계 규칙을 만듭니다. 우선 건물 1개당 보조 조합은 최대 1개로 제한합니다. 장독대의 여러 항아리는 하나의 조합으로 취급하고, 같은 셀에 기존 두 번째 슬롯 소품을 추가로 중복 배치하지 않습니다.

**구현 영향:** 부모 배치 ID와 역할 이름에서 소품 시드를 파생하고, 접지점 기준 로컬 오프셋을 고정합니다. 팔레트·모션·렌더 호출 순서는 시드에 넣지 않습니다. 소품이 공간을 벗어나면 추가 후보를 무작정 탐색하기보다 짧은 담장/단순 장식으로 줄이거나 생략합니다. 기여 셀의 위치·날짜를 옮겨 마당을 넓히지 않으며, 새 길과 경작 조합은 0일 또는 누락일을 활동 공간처럼 채우지 않습니다. 기존 자연 장식과 새 활동 조합을 구별해야 합니다. [장면 배치](../src/themes/terrain/scene/placements.ts), [깊이 정렬](../src/themes/terrain/scene/depth.ts).

**통과 기준:** 장독대의 기준점이 지정된 부모 집의 마당 범위에 있고, 같은 입력을 반복 렌더하면 부모·소품 ID와 오프셋이 같습니다. 데이터 범위를 바꾸면 달라질 수 있는 이웃 길/가림과, 같은 날짜의 고정 소품 시드는 구별해서 검증합니다. 장면 전체가 범위 변경에도 항상 동일하다고 약속하지 않습니다.

### 5. 픽셀아트는 원화·투영·배율을 함께 바꿉니다

제작자 Pedro Medeiros는 픽셀을 의도적으로 배치하고, 기준 해상도를 유지하며, 정수 배율과 nearest-neighbor 확대를 사용하는 방식을 설명합니다. 작은 원화를 임의로 축소하거나 서로 다른 격자를 섞으면 결과가 달라집니다. [제작자의 배율 설명](https://saint11.art/blog/scaling/), [장면 내부의 해상도 일관성](https://saint11.art/blog/consistency/).

SVG의 `shape-rendering="crispEdges"`는 렌더링 힌트이며, 기존 곡선을 픽셀 원화로 재설계하는 기능이 아닙니다. CSS `image-rendering: pixelated`도 비정수 배율에서 중간 보간을 허용하므로 정수 격자 자체를 대신하지 못합니다. [W3C SVG의 렌더링 힌트](https://www.w3.org/TR/SVG2/painting.html#ShapeRenderingProperty), [W3C 이미지 배율 규칙](https://www.w3.org/TR/css-images-3/#the-image-rendering).

**제안하는 경로:**

1. 문화 스타일과 별개인 아트 설정을 추가하고, 픽셀 세계에는 하나의 논리 격자를 사용합니다. 시작 검토안은 **8×4 논리 픽셀 타일과 약 320×200 기본 캔버스**입니다. 에셋은 이 격자에 직접 그리고, 지형 높이·접지점·그림자·장식 좌표도 정수로 맞춥니다. 16×8 타일은 큰 출력용 대안입니다.
2. 현재 16×7 투영의 `THH = 3.5`와 소수 배율 `fitScene`을 그대로 재사용하지 않습니다. 53주×7일을 16×8 타일로 펼치면 지면만 세로 약 240 논리 픽셀이어서 현재 배너의 장면 높이 175에 1배로 들어가지 않습니다. 픽셀 전용 뷰포트와 높이 상한을 함께 정하고, 윤년·부분 주를 포함한 실제 bounds로 검증합니다. 잘 맞지 않는 캔버스는 키우며 날짜를 자르거나 임의 축소하지 않습니다. [현재 투영](../src/themes/terrain/scene/projection.ts), [현재 뷰포트](../src/themes/terrain/scene/bounds.ts).
3. Aseprite 원화에서 팔레트·프레임·접지점을 관리합니다. 제작 시 내보낸 픽셀을 기존 Node/tsx 단계에서 **같은 색의 연속 구간을 묶은 정수 좌표 SVG path**로 변환하는 방식을 우선 비교합니다. 픽셀 하나마다 DOM 요소를 만들지 않습니다. Aseprite의 CLI는 PNG 시트와 JSON 메타데이터 출력을 지원하지만, SVG 구간 변환기는 프로젝트에서 별도로 만들어야 합니다. [Aseprite 공식 CLI](https://www.aseprite.org/docs/cli/#data).
4. 원본 SVG에는 필요한 도형과 팔레트를 자체 포함합니다. PNG `data:` 포함도 비교 가능한 대안이지만, 테마·계절별 비트맵 크기와 현재 PNG 출력기 호환성을 먼저 확인해야 합니다. 외부 스프라이트 URL은 사용하지 않습니다. SVG 이미지 처리 모드는 스크립트·외부 참조를 제한하며, 문서 내부 참조와 `data:` 참조를 별도로 취급합니다. [W3C SVG 처리 모드](https://www.w3.org/TR/SVG2/conform.html#processing-modes), [현재 PNG 출력기](../src/output/png.ts).
5. 밝은/어두운 모드와 계절은 제한된 색 역할을 교체하고 픽셀 배치를 유지합니다. 통계 문자는 세계와 분리된 영역에 둘 수 있지만, 세계 안에 부드러운 벡터 구름·서브픽셀 회전·흐린 그림자를 섞지 않습니다.

**출력 계약:** 기본 크기와 2배 크기를 제공하되, 픽셀 정렬을 보장하는 조건은 정수 배율·정렬된 위치·검증된 DPR/줌으로 한정합니다. 예를 들어 320px 기본 출력은 390px 화면에서도 320px로 표시할 수 있습니다. 640px 출력을 소비자가 390px로 축소하면 같은 품질을 보장할 수 없습니다. 브라우저 확대율과 외부 README 레이아웃까지 출력 파일이 강제할 수는 없습니다.

**통과 기준:** `pine / hanok / ricePaddy`와 0·저·고기여 타일을 1배·2배로 먼저 제작하고, 전체 달력이 손실 없이 들어가는지 확인합니다. DPR 1·2의 지정 크기에서 계단 간격과 선 굵기를 점검하며, 390px 강제 축소는 별도의 제한 사례로 기록합니다. 픽셀아트는 그림의 저장 형식이 아니라 원화와 격자의 설계 방식으로 판정합니다.

### 6. 정적 보상을 먼저 완성하고 강조 모션을 제한합니다

현재 렌더러는 모션이 꺼진 가지와 활성 가지를 분리하고, 환경의 모션 감소 설정에 따라 정적인 표현을 보여주는 구조를 갖고 있습니다. 이 구조에 맞춰 고기여 보상도 처음 프레임부터 완결되어야 합니다. [현재 모션 분기](../src/themes/terrain/motion/index.ts). W3C의 `prefers-reduced-motion` 정의는 모션을 줄이거나 대체하려는 사용자 선호를 다룹니다. 해당 인용 문서는 작업 초안이며, 구현 호환성의 실측 결과는 아닙니다. [W3C Media Queries Level 5](https://www.w3.org/TR/mediaqueries-5/#prefers-reduced-motion).

**제안:** 높은 보상 단계 중 최대 3개 날짜만 약하게 강조합니다. 단계 내에서는 기여 수 내림차순·날짜 오름차순으로 선택하고, 새 강조 효과는 예를 들어 1.2초×3회 뒤 정적 표현으로 돌아오게 합니다. 상위 3개에 들지 못한 날짜도 보상 기하 요소는 그대로 유지합니다. 픽셀 버전의 모션이 필요하면 미리 그린 격자 프레임을 교체하고, 도형을 소수 각도로 흔들지 않습니다.

**구현 영향:** 신규 효과에 독립된 예산을 더하지 않고 전체 장면 예산에서 할당합니다. 현재 코드는 일반 에셋 SMIL 후보 18개·CSS 후보 15개, 물 15개·반짝임 10개 등으로 선택 한도가 분산되어 있습니다. 프로젝트 문서의 총 50개 정책을 실제 활성 애니메이션으로 세어 검증해야 하며, 이번 조사에서는 전체 효과를 합산하거나 50개 준수 여부를 실측하지 않았습니다. 한 에셋의 여러 `<animate>`와 CSS 효과도 고려해야 합니다. [일반 모션 선택](../src/themes/terrain/assets/selection.ts), [효과 제한](../src/themes/terrain/effects/css.ts), [프로젝트 정책](../CLAUDE.md).

**통과 기준:** `off`, `subtle`, `full`, 모션 감소 환경, 정적 PNG에서 날짜별 보상 단계와 에셋 위치가 같습니다. `off` 출력에는 애니메이션 요소가 없어야 하고, 새 강조 효과는 최대 3개·정해진 반복 횟수를 지켜야 합니다. SVG를 직접 여는 경우와 HTML `<img>`에 넣은 경우를 각각 확인합니다. 정적 SVG는 외부 스크립트 없이 의미가 완결되고, 애니메이션은 선택적인 부가 표현이어야 합니다.

### 7. 아트 버전과 제작 정보를 묶고 확장 전 비용을 확인합니다

현재 `layoutVersion: 1`과 설정/스냅샷 계약이 있지만, 문화 스타일과 독립된 아트 버전은 별도 검토가 필요합니다. 그림을 바꾸는 것과 과거 스냅샷의 그림까지 재현하는 것은 다른 요구입니다. [장면 타입](../src/core/scene-types.ts), [설정 스키마](../src/core/settings/schema.ts), [스냅샷 스키마](../src/core/settings/snapshot-schema.ts).

**제안:** 대표 에셋부터 아트 버전, 접지점, 최댓값 bounds, 팔레트 역할, 간략/상세 표현, 픽셀 논리 크기, 정적 프레임, 제작/권리 출처를 함께 관리합니다. 기존 SVG는 기본 아트 버전으로 해석하고, 픽셀아트를 선택할 때는 같은 문화 스타일을 유지할 수 있게 합니다. 과거 원화를 배포에 보존하지 않을 경우 ‘동일 데이터와 배치는 재현하지만 과거 그림의 바이트 일치는 보장하지 않는다’는 계약을 명시해야 합니다.

**구현 영향:** 설정을 추가한다면 CLI·Action·브라우저 입력·저장/불러오기·스냅샷을 함께 다뤄야 합니다. 렌더러 내부 옵션 하나만 추가하면 재실행 시 그림체를 잃을 수 있습니다. 원화는 자체 제작을 기본으로 하고, 참고 자료의 열람 권한과 재배포 권리를 혼동하지 않습니다. Node/npm/tsx/Vitest/ESLint/Prettier 체계를 유지하며, 제작 도구는 사용자 실행 환경의 필수 런타임으로 넣지 않습니다.

**통과 기준:** 기존 카탈로그 도구로 동일 12종의 실제 크기·확대 크기와 계절/모드 차이를 검수한 뒤 확장합니다. 기존 벤치마크는 동일 fixture에서 원본 크기·gzip 크기·요소 수 +5%, 비교 가능한 환경에서 중앙값 +20%·p95 +30%를 한도로 둡니다. 이 기준을 활용하고, 픽셀 대안도 벡터 대비 비용을 보고 선택합니다. 새로운 아트가 더 빠르거나 더 작다는 주장은 측정 후에만 할 수 있습니다. [카탈로그 생성기](../scripts/generate-catalog.ts), [기존 예산 검사](../scripts/benchmark/budgets.ts).

## 첫 구현 묶음과 검증 범위

첫 묶음은 **확정 보상 + 한옥·초가·소나무·논·장독대·정자의 작은 크기 조합**을 권합니다. 기여가 늘어도 한국 시골의 정체성이 유지되는지 먼저 확인할 수 있습니다. 픽셀아트는 같은 데이터와 소재로 정수 격자 비교본을 제작해 출력 제약을 확인한 후 전체 카탈로그 확장 여부를 판단합니다.

| 검증 상황                                          | 확인할 결과                                                               |
| -------------------------------------------------- | ------------------------------------------------------------------------- |
| 모두 0, 일부 날짜 누락, 단 하루 100회 기여         | 가짜 활동 없이 단독 고기여일의 정적 보상이 존재합니다.                    |
