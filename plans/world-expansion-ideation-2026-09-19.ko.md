# 하늘 마을의 다음 방향: 내 기록으로 자라는 작은 세계

작성일: 2026-09-19. 코드 확인 기준: `05a10eff07575acf2c81adcd66a66bc501507217`.

이 문서는 **아이디에이션과 우선순위 제안**입니다. 구현 범위·일정의 확정이나 새 기능의 구현 완료를 뜻하지 않습니다. 아래 난도·비율·개수는 현재 구조를 보고 제안한 초기 가설이며 실측 결과가 아닙니다.

**가장 추천하는 방향은 ‘자연과 작은 도시가 공존하는 하늘 군도’입니다.** 월별 섬에 숲·호수·한옥마을·기차역이 생기고, 활동이 쌓이면 섬 사이에 길과 생활 장면이 연결됩니다. GitHub에서는 대표 풍경을 보고, 웹에서는 그 세계를 확대하거나 3D로 탐험하는 경험을 제안합니다.

## 현재 갖춰진 것과 새로 필요한 것

현재는 날짜별 기여량을 등각 SVG 지형으로 만듭니다. 배너·카드, 두 화풍과 두 문화 스타일, 사계절, 자연 중심 배치, 꾸준함 효과, 브라우저 확대·날짜 조회, 스냅샷과 여러 해 비교가 이미 있습니다. 따라서 단순히 ‘계절·줌·연도 비교를 추가하자’는 기존 기능과 중복됩니다. [현재 사용법](../README.md)

`TerrainScene`에는 날짜·기여 수·높이·바이옴·에셋 ID·변형·배치가 있고, 브라우저에서도 `prepareTerrainScene`과 렌더러를 별도로 사용할 수 있습니다. 새로운 지도와 3D 뷰가 활용할 출발점입니다. 다만 `isoX`, `isoY`, 배치 좌표·경계는 2D 등각 그림을 기준으로 하므로, 새 공간 좌표와 에셋별 입체 모델은 별도로 설계해야 합니다. [장면 타입](../src/core/scene-types.ts), [브라우저 API](../src/browser.ts)

GitHub에 이미지로 삽입한 SVG 안에서 회전·클릭 이동 같은 JavaScript 탐험 기능을 실행하는 방식은 적절하지 않습니다. 이미지 문맥의 SVG에는 스크립트 실행 제한이 있습니다. **대표 SVG/PNG에 탐험 페이지 링크를 연결하는 구성**을 권합니다. [MDN: SVG as an image](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image)

## 땅이 넓어질 때의 구체적인 형태

- **월별 군도 — 추천 기본안:** 한 달의 실제 날짜들을 하나의 섬 안에 배치하고, 바깥에 해안·절벽·산책길 같은 풍경 공간을 둡니다. 1일·15일·말일 등 날짜 표식을 선택적으로 보여줍니다. 달력 연도는 12개 섬이며, 이동하는 1년 범위는 두 해의 부분 월을 포함할 수 있으므로 `YYYY-MM` 식별자를 사용합니다.
- **하나의 큰 섬 — 대안:** 한 해를 넓은 지형에 배치하고 중심 호수·숲·시가지로 나눕니다. 연속된 풍경은 강점이지만 날짜 순서를 읽기 위한 월 경계·시간축이 더 중요합니다.
- **여러 해의 세계 — 장기 확장:** 연도별 군도를 보관하고 세계 지도에서 이동합니다. 데이터가 늘 때 과거 장소 전체가 재배치되지 않도록 좌표와 생성 규칙의 버전을 보관합니다.

섬을 확장해도 날짜가 없는 장식 땅을 기여가 있었던 칸으로 계산하지 않습니다. 관측한 0회 기여일, 제공되지 않은 날짜, 순수 배경 공간을 구분해야 합니다. 넓은 지도 전체를 작은 배너에 축소하면 에셋이 다시 작아지므로, 프로필 표지에는 대표 구도나 선택한 계절 지역을 쓰고 웹에서 전체 지도를 펼치는 방식도 비교할 만합니다.

## 도시와 자연이 조화롭게 보이게 하는 규칙

도시는 역·시장·광장·주택가처럼 역할이 있는 작은 지역으로 구성합니다. 한옥촌, 한국 시골, 해안 소도시, 숲속 역을 서로 다른 지역 테마로 두고, 하천·논밭·숲을 통해 이어지게 하면 좋겠습니다. 초기 시안에서는 **배치 가능한 육지 면적의 70~80%를 자연·열린 공간에 두는 구성**을 비교 후보로 제안합니다. 이 수치는 공식 자료에서 얻은 최적값이 아니라 사용자의 자연 선호에 맞춘 가설입니다.

새 도시에서도 반복을 줄이는 기준은 단순한 에셋 ID 개수보다 실루엣입니다. 건물의 높이·지붕·방향·마당과 나무의 수관·군집·빈 공간을 함께 비교해야 합니다. 멀리서 봤을 때도 숲, 작은 마을, 역 주변이 구별되는지가 중요합니다.

## 기여량과 꾸준함을 재미로 연결하는 방식

| 기록의 의미 | 표현 제안 | 예시 |
| --- | --- | --- |
| 하루의 활동량 | 해당 날짜의 주 보상과 세부 표현이 풍부해짐 | 큰 고목의 수관, 바위 계곡의 물줄기, 정교한 정자와 마당 |
| 최근 일정 기간의 활동 | 생활 장면·길·계절 행사의 풍부함 | 꽃길에 나비가 모이고, 장터 천막이 펴지고, 나룻배가 오감 |
| 월·연도의 누적 기록 | 그 시기의 기념 장소와 보관할 풍경 | 월말의 전망대, 연말의 대표 엽서, 기록을 설명하는 표지판 |
| 다시 방문 | 새로 생긴 장소를 찾아가는 짧은 안내 | ‘지난 방문 이후 숲길에 작은 역이 생겼어요’ |

활동량에 따라 세계의 디테일과 이야기가 달라지게 하되, 모든 단계에 좋은 기본 그림을 제공합니다. 낮은 활동량에서도 여백 있는 아름다운 풍경이 남아야 합니다. 같은 종류를 많이 쌓는 방식은 다시 반복 문제로 이어질 수 있으므로 활동 보상은 종류·주변 구성·연결·생활 변화로 나눕니다.

현재 입력은 GitHub 일별 기여 합계이므로 이를 커밋 수나 작업의 품질과 동일하게 설명하면 안 됩니다. 쉬는 날 때문에 기존 숲이나 마을을 철거하는 규칙은 권하지 않습니다. 과거 풍경 보존은 저장 시점과 생성 버전을 명시해야 하며, 현재 이동 기간의 재계산만으로 영구 보존이 보장되는 것은 아닙니다.

## 3D의 현실적인 제작 방향과 도구

**작은 모형을 손으로 돌려 보는 듯한 입체 미니어처**가 현재 그림과 가장 잘 이어질 것으로 판단합니다. 정투영 카메라, 부드러운 그림자, 절제된 물 표현, 여러 실루엣의 나무와 낮은 건물로 시작하면 좋겠습니다. 초기에 자유 보행보다 회전·확대·장소 선택·사진 모드를 우선하면 조작과 에셋 품질에 집중할 수 있습니다.

| 도구·기술 | 공식 기능과 적용 판단 |
| --- | --- |
| Three.js `OrthographicCamera` | 거리에 따라 물체의 화면 크기가 변하지 않는 정투영을 제공합니다. 현재 등각 미니어처와 연결되는 카메라 후보입니다. [공식 문서](https://threejs.org/docs/pages/OrthographicCamera.html) |
| Three.js `OrbitControls` | 회전·줌·화면 이동을 제공합니다. 섬을 돌려 보는 첫 탐험에 적합한 후보입니다. [공식 문서](https://threejs.org/docs/pages/OrbitControls.html) |
| Three.js `InstancedMesh` | 같은 기하·재질의 여러 물체를 그릴 때 draw call을 줄일 수 있습니다. 나무 종류·실루엣별로 묶고 크기·방향을 달리하는 방법을 시험할 수 있습니다. 다른 메시를 모두 한 번에 처리해 주는 것은 아닙니다. [공식 문서](https://threejs.org/docs/pages/InstancedMesh.html) |
| Blender → glTF/GLB → `GLTFLoader` | Blender의 glTF 내보내기와 Three.js의 glTF 2.0 로더를 연결하는 모델 제작 경로입니다. [Blender 공식 매뉴얼](https://docs.blender.org/manual/en/4.0/addons/import_export/scene_gltf2.html), [Three.js 공식 로더](https://threejs.org/docs/pages/GLTFLoader.html) |

현재 SVG의 앞모습을 평면에 붙이는 것만으로는 뒤쪽에서도 완성된 3D 모델이 되지 않습니다. 실제 입체 에셋은 모든 관찰 각도에서의 실루엣·재질·계절 변화를 새로 만들어야 합니다. 따라서 전체 에셋 수보다 먼저 작은 섬의 나무·물·지붕 품질을 확인하는 것이 좋겠습니다.

3D 뷰는 요청할 때 불러오는 별도 웹 진입점으로 두고, 기존 SVG 생성 경로와 구분해 구성할 수 있습니다. 모바일에서는 그림자·입자·표시 거리를 줄이는 품질 선택지를 평가하고, 움직임 끄기와 정적 이미지도 제공하는 편이 좋겠습니다. 성능 개선이나 특정 프레임 속도는 이번 조사에서 측정하지 않았습니다.

## 다음 결정을 위한 추천 묶음

**가장 먼저 비교할 시안은 ‘월별 군도 + 숲·한옥·작은 도시의 지역 구분’입니다.** 여기에 나룻배나 짧은 열차 노선 한 개를 넣으면 넓어진 땅을 탐험할 이유가 생깁니다. 이 장면을 기존 화풍과 작은 3D 섬으로 비교하면 사용자가 좋아하는 품질 방향을 구체적으로 고를 수 있습니다.

이후에는 계절 행사·생활 움직임, 사진 모드, 시간 재생이 자연스럽게 이어집니다. 프로젝트별 도시와 친구 방문은 추가 데이터와 공유 경험이 필요하므로, 개인 세계의 매력이 확인된 뒤 확장하는 후보로 두는 편을 권합니다.

이번에는 코드와 공식 자료를 읽고 제안 문서 두 개를 작성했습니다. 새 기능의 구현·성능 측정·사용자 선호 검증은 수행하지 않았습니다.
